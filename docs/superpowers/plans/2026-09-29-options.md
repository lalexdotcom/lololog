# One-shot Options Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `L.options({ datetime })`: a view whose level methods (with `spin` and `exec`) emit with `datetime` overridden, without touching the logger's state, chainable with `limit` / `once` in both orders.

**Architecture:** `src/overrides.ts` validates and copies the options object (`checkOptions`). The overrides travel as an optional last parameter of the loggers' `write` and `spin`, which resolve `overrides?.datetime ?? scope ?? root ?? false`. `src/options.ts` holds `OptionsView` (level methods built by per-level getters, so `.spin` / `.exec` know the view; `limit` / `once` on its prototype); `LimitedView` in `src/limit.ts` gains an `overrides` field and an `options()` method.

**Tech Stack:** TypeScript (`tsc`), rstest 0.12 (projects `node`, `browser-chromium`, `browser-firefox`, `browser-webkit`), Biome, rslib, pnpm, tsx.

**Spec:** `docs/superpowers/specs/2026-09-29-options-design.md`

## Global Constraints

- Branch `feat/options` (already checked out, holds the spec commit). Never a git worktree.
- Imports are relative and extensionless (`from "./overrides"`).
- `src/` references no Node global and has no Node types (`tsconfig.build.json`, `types: []`).
- Module graph: `src/overrides.ts` imports nothing; `src/limit.ts` and `src/options.ts` both import it and never import each other in a cycle (`options.ts` imports `limit.ts`, not the reverse); `options.ts` imports from `src/logger.ts` with `import type` only.
- Only overridable setting: `datetime`. Key name `datetime`. `datetime: undefined` means no override.
- Validation at the `options()` call, strict: `TypeError` for a non-object, `null`, an array, an own key (from `Object.keys`) other than `datetime`, a `datetime` neither boolean nor `undefined`. Messages: `lololog: options must be an object`, `lololog: unknown option "<key>"`, `lololog: invalid datetime <value>`.
- A chain holding a limit offers the plain call only (no `spin`, no `exec`). One `options()` per chain, enforced by types only.
- `LogOptions` is exported from `src/index.ts` as a type; `OptionsMethods`, `LimitedMethods`, `PlainMethods` are not.
- Comments say why, never what; one only where a reader would otherwise get it wrong.
- Every test file runs in the four rstest projects. Test helpers never call lololog in tail position (`return f()`, arrow expression body): JavaScriptCore drops the caller's frame and keyless limits shift.
- After each modification: `pnpm exec biome check --write <touched files>`, then `pnpm typecheck`.
- Commits follow Conventional Commits, body explains why, and end with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- A user-visible change updates `CHANGELOG.md` under `## [Unreleased]` / `### Added` (and the README when it documents the API) in the same commit.
- Subagents touching code use Serena's symbolic tools first (`get_symbols_overview`, `find_symbol`, `replace_symbol_body`, `insert_after_symbol`, `replace_content`), built-in Read/Edit on code only as fallback; every subagent prompt carries this rule.

## Review Focus

1. An options object without a prototype (`Object.create(null)`, as built by some config loaders): accepted like `{}` (Task 1).
2. A root or scope switched off with `enabled = false`: `L.options(o).info(…)` stays silent — the override never lets a line escape (Task 2).
3. A filtered level: `options(o).info.spin` returns the shared inert spinner and `exec` still runs its task and resolves (Task 2).
4. One options view hoisted and reused across levels and many calls: every call carries the override (Task 2).
5. A keyless `options(o).once()` reached from two call sites: one line per site, as with `once()` alone (Task 3).

```ts
export interface LogOptions {
	datetime?: boolean;
}

export function checkOptions(options: unknown): LogOptions {
	if (typeof options !== "object" || options === null || Array.isArray(options)) {
		throw new TypeError("lololog: options must be an object");
	}
	// Plain JS gets no excess-property check: a setting that cannot be overridden (`color`) or a
	// typo (`date`) would otherwise be dropped without a word, and the line would come out unchanged.
	for (const key of Object.keys(options)) {
		if (key !== "datetime") throw new TypeError(`lololog: unknown option ${JSON.stringify(key)}`);
	}
	const { datetime } = options as LogOptions;
	if (datetime !== undefined && typeof datetime !== "boolean") {
		throw new TypeError(`lololog: invalid datetime ${String(datetime)}`);
	}
	// A copy: a spinner re-reads its datetime at every frame, so the caller's object must not
	// stay reachable.
	return { datetime };
}
```

```ts
import { LEVEL_NAMES, LEVELS, type Level } from "./levels";
import type { LimitHost } from "./limit";
import type { LevelMethod, LevelMethods } from "./logger";
import type { LogOptions } from "./overrides";
import { exec } from "./spinner/exec";
import type { InitialSpinnerOptions, Spinner } from "./spinner/spinner";

export type OptionsMethods = LevelMethods;

export interface OptionsHost extends LimitHost {
	spin(
		level: Level,
		severity: number,
		message: string,
		options: InitialSpinnerOptions | undefined,
		overrides?: LogOptions,
	): Spinner;
}

export class OptionsView {
	readonly host: OptionsHost;
	readonly overrides: LogOptions;

	constructor(host: OptionsHost, overrides: LogOptions) {
		this.host = host;
		this.overrides = overrides;
	}
}

// Getters, not prototype functions: in `view.info.spin(…)` the spin closure must reach the view,
// and a function shared on the prototype only sees `view.info` as `this`. Not closures built in
// the constructor either: `L.options(o)` runs once per call, and only the level read pays here.
for (const level of LEVEL_NAMES) {
	const severity = LEVELS[level];
	Object.defineProperty(OptionsView.prototype, level, {
		get(this: OptionsView): LevelMethod {
			const { host, overrides } = this;
			const method = ((...args: unknown[]) =>
				host.write(level, severity, args, overrides)) as LevelMethod;
			method.spin = (message, options) => host.spin(level, severity, message, options, overrides);
			method.exec = (message, task, options) => exec(method.spin(message, options), task);
			return method;
		},
	});
}

export function createOptions(host: OptionsHost, overrides: LogOptions): OptionsMethods {
	return new OptionsView(host, overrides) as unknown as OptionsMethods;
}
```

import { L } from "/workspaces/lololog/dist/index.js";

const sink = console.log;
console.log = () => {};
L.format = "json";

function median(run: () => void, rounds = 15, calls = 200_000): number {
	const samples: number[] = [];
	for (let r = 0; r < rounds; r++) {
		const start = process.hrtime.bigint();
		for (let i = 0; i < calls; i++) run();
		samples.push(Number(process.hrtime.bigint() - start) / calls);
	}
	samples.sort((a, b) => a - b);
	return samples[Math.floor(rounds / 2)];
}

L.level = "info";
const results = {
	"filtered L.debug": median(() => L.debug("x")),
	"filtered L.options(o).debug": median(() => L.options({ datetime: true }).debug("x")),
	"filtered L.limit(1).debug": median(() => L.limit(1).debug("x")),
	"emitted L.info (json)": median(() => L.info("x")),
	"emitted L.options(o).info (json)": median(() => L.options({ datetime: true }).info("x")),
};
console.log = sink;
for (const [name, ns] of Object.entries(results)) console.log(`${name}: ${ns.toFixed(1)} ns`);
